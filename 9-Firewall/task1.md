#Открываем iptables

Был выполнен просмотр текущих правил iptables. В результате было установлено, что все цепочки (INPUT, FORWARD, OUTPUT) имеют политику ACCEPT, а пользовательские правила отсутствуют. Это означает, что на данный момент firewall не блокирует сетевые подключения.

#Установите iptables

Пакет iptables был успешно установлен в системе. Установка прошла без ошибок, что подтверждается выводом менеджера пакетов и возможностью выполнить команду просмотра правил iptables.

Проверьте, осталась ли возможность подключения по SSH к вашему серверу

После установки iptables возможность подключения по SSH сохранилась. Это объясняется тем, что политика цепочки INPUT установлена в значение ACCEPT, а ограничивающих правил не задано.

#Почему может пропасть такая возможность?

Возможность подключения по SSH может пропасть в случае изменения политики цепочки INPUT на DROP или REJECT, а также при отсутствии разрешающего правила для порта SSH. В этом случае входящие соединения по SSH будут блокироваться firewall.

#Откройте нужный порт на сервере, чтобы восстановить подключение

Для восстановления подключения необходимо добавить правило, разрешающее входящие соединения на порт, используемый SSH-сервером. Это правило должно быть добавлено в цепочку INPUT.

Это будет UDP или TCP протокол?

Для подключения по SSH используется протокол TCP, так как SSH работает поверх TCP-соединений.

Сохраняем

После добавления правил их необходимо сохранить, чтобы они могли быть повторно применены в дальнейшем.

Сохраняются ли записанные вами правила после перезагрузки?

По умолчанию правила iptables не сохраняются после перезагрузки системы, так как они хранятся в оперативной памяти.

Как их сохранить?

Для сохранения правил используется механизм сохранения конфигурации iptables, например с помощью утилиты iptables-save, либо через специализированные сервисы сохранения правил, обеспечивающие их автоматическую загрузку при старте системы.
